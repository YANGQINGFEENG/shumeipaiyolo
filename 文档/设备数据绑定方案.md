# 设备数据绑定方案

## 更新日期：2026-07-26

---

## 核心概念

### 设备网关（Gateway）
- 有独立IP的设备，可以是：
  - 单个WiFi传感器（自身就是网关）
  - 多传感器聚合器（LoRa/Zigbee网关）
  - 工业网关（RS485转WiFi）
- **区域划分**：同一IP地址的设备默认属于同一区域

### 设备节点（Node）
- 没有独立IP的传感器或执行器
- 通过网关上报数据
- 有唯一设备ID（MAC或序列号）

### 设备类别（Category）
- **传感器（Sensor）**：采集环境数据的设备（温度、湿度、光照等）
- **执行器（Actuator）**：执行控制指令的设备（水泵、风扇、电机、舵机等）
- **网关（Gateway）**：数据传输和聚合设备

### 执行器控制类型
- **boolean**：布尔值控制（on/off）- LED开关、继电器、水泵等
- **integer**：整数值控制（0-100）- 电机速度、亮度调节等
- **angle**：角度控制（0-180/360）- 舵机角度、阀门开度等
- **float**：浮点值控制 - 精确参数调节
- **string**：字符串指令 - 自定义指令

## 区域划分机制

### 区域划分规则

1. **网关级区域**：优先使用上报数据中的 `area` 字段
2. **IP默认区域**：如果没有提供 `area` 字段，使用 `gateway_ip` 生成默认区域名（如：区域-192.168.1.100）
3. **节点级覆盖**：单个设备可以通过 `nodes[].area` 字段覆盖网关级区域设置
4. **同一IP同一区域**：同一IP地址的设备默认属于同一区域

### 区域字段分布

| 表名 | 字段 | 说明 |
|------|------|------|
| gateways | area | 网关所属区域 |
| sensors | area | 传感器所属区域 |
| actuators | area | 执行器所属区域 |
| device_nodes | area | 设备节点所属区域 |

## 数据库设计

```sql
-- 设备网关表
CREATE TABLE gateways (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    farm_id INTEGER NOT NULL,
    zone_id INTEGER,
    name TEXT NOT NULL,
    gateway_type TEXT NOT NULL,  -- wifi_sensor/lorawan_gateway/serial_gateway
    ip_address TEXT,
    mac_address TEXT,
    protocol TEXT,               -- mqtt/http/lorawan
    status TEXT DEFAULT 'online',
    area TEXT DEFAULT '',        -- 区域名称
    last_heartbeat TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (farm_id) REFERENCES farms(id)
);

-- 设备节点表（挂在网关下）
CREATE TABLE device_nodes (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    gateway_id INTEGER NOT NULL,
    node_id TEXT NOT NULL,        -- 设备唯一ID（MAC/序列号）
    name TEXT NOT NULL,
    node_type TEXT NOT NULL,      -- sensor/actuator
    sensor_type TEXT,             -- temperature/humidity/light等
    location TEXT,
    config TEXT,                  -- JSON配置
    status TEXT DEFAULT 'online',
    area TEXT DEFAULT '',         -- 区域名称
    last_update TIMESTAMP,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (gateway_id) REFERENCES gateways(id),
    UNIQUE(gateway_id, node_id)
);

-- 设备数据表（统一存储所有数据）
CREATE TABLE device_data (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    gateway_id INTEGER NOT NULL,
    node_id TEXT NOT NULL,
    sensor_type TEXT NOT NULL,
    value REAL NOT NULL,
    unit TEXT,
    quality INTEGER DEFAULT 100,  -- 数据质量 0-100
    timestamp TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (gateway_id) REFERENCES gateways(id)
);

-- 执行器表（含控制类型配置）
CREATE TABLE actuators (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type_id INTEGER NOT NULL,
    location TEXT NOT NULL,
    status TEXT DEFAULT 'offline',
    state TEXT DEFAULT 'off',
    mode TEXT DEFAULT 'auto',
    control_value REAL,           -- 当前控制值（电机速度、舵机角度等）
    control_type TEXT DEFAULT 'boolean',  -- 控制类型：boolean/integer/angle/float/string
    control_min REAL DEFAULT 0,   -- 控制最小值
    control_max REAL DEFAULT 100, -- 控制最大值
    control_step REAL DEFAULT 1,  -- 控制步进值
    control_default REAL DEFAULT 0, -- 控制默认值
    area TEXT DEFAULT '',         -- 区域名称
    farm_id INTEGER DEFAULT 0,
    zone_id INTEGER,
    last_update TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    locked INTEGER DEFAULT 0      -- 锁定状态（控制指令执行中为1）
);

-- 传感器表
CREATE TABLE sensors (
    id TEXT PRIMARY KEY,
    name TEXT NOT NULL,
    type_id INTEGER NOT NULL,
    location TEXT NOT NULL,
    status TEXT DEFAULT 'offline',
    battery INTEGER DEFAULT 100,
    area TEXT DEFAULT '',         -- 区域名称
    farm_id INTEGER DEFAULT 0,
    zone_id INTEGER,
    last_update TIMESTAMP NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- 执行器控制指令表
CREATE TABLE actuator_commands (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    actuator_id TEXT NOT NULL,
    command TEXT NOT NULL,        -- on/off/value
    control_value REAL,           -- 控制值（command=value时使用）
    status TEXT DEFAULT 'pending', -- pending/executing/executed/failed/timeout
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    executed_at TIMESTAMP NULL
);
```

## 控制指令回执协议

### 硬件端发送回执

```json
POST /api/device/ack
{
    "gateway_ip": "192.168.1.100",
    "actuator_id": "MT-1-1001",
    "command_id": 123,
    "status": "executed",
    "control_value": 75,
    "state": "on"
}
```

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| gateway_ip | string | ❌ | 网关IP地址 |
| actuator_id | string | ✅ | 执行器ID |
| command_id | number | ✅ | 命令ID |
| status | string | ✅ | 执行状态：executed / failed |
| control_value | number | ❌ | 实际控制值 |
| state | string | ❌ | 执行器状态：on / off |

### 超时机制

- 控制指令发送后，服务器等待 **30秒** 回执
- 超时未收到回执，标记为 `timeout` 并提醒用户
- 超时后执行器自动解锁，允许重新发送指令

## 自动绑定逻辑

1. **首次上报**：自动创建网关和设备节点
2. **设备类型识别**：根据 `type` 字段自动识别设备类别（传感器/执行器）
3. **设备自动分类**：传感器数据同步到 `sensors` 表，执行器数据同步到 `actuators` 表
4. **ID自动生成**：统一生成格式 `{PREFIX}-{gatewayId}-{nodeId}`（如 T-1-001）
5. **类型自动创建**：新设备类型自动注册到 `sensor_types` 或 `actuator_types` 表
6. **IP/MAC匹配**：后续上报自动关联到已有设备
7. **基地绑定**：通过网关的 farm_id 关联到基地
8. **区域自动划分**：根据网关IP自动划分区域，支持自定义区域名称
9. **控制类型自动加载**：硬件上报 `control_type` 后，前端自动加载对应控制卡片
10. **回执确认机制**：控制指令发送后等待硬件回执，收到回执才更新页面状态

## 支持的设备类型

| 类型标识 | 名称 | 单位 | 前缀 | 适用传感器 |
|----------|------|------|------|------------|

| humidity | 空气湿度 | % | H | DHT11、SHT30、SHT40 |
| light | 光照强度 | lux | L | BH1750、TSL2561 |
| soil_moisture | 土壤湿度 | % | SM | FC-28、YL-69、SHT30 |
| soil_temperature | 土壤温度 | °C | ST | DS18B20、土壤温度传感器 |
| ph | 土壤pH值 | pH | P | pH传感器模块 |
| ec | 土壤电导率 | μS/cm | EC | EC传感器模块 |
| co2 | CO2浓度 | ppm | C | MH-Z19B、SCD30 |
| pm25 | PM2.5 | μg/m³ | PM | PMS5003、PMS7003 |
| water_level | 水位 | cm | WL | 超声波水位传感器 |
| pressure | 气压 | hPa | PR | BMP280、BME280 |
| vibration | 振动 | mm/s | VB | SW-420振动传感器 |
| altitude | 海拔 | m | AL | BMP280、BME280（计算得出） |

| heater | 加热器 | HT | boolean | 加热棒、加热垫 |
| valve | 电磁阀 | VL | boolean | 继电器、电磁阀模块 |
| light | 补光灯 | LT | boolean | LED补光灯、激光灯 |
| ventilator | 通风机 | VT | integer | 排风扇、通风机 |
| fogger | 雾化器 | FG | boolean | 雾化喷头、超声波雾化器 |
| motor | 电机 | MT | integer | 电机驱动、速度控制 |
| servo | 舵机 | SV | angle | 舵机角度控制 |

## 控制卡片自动加载逻辑

根据执行器的 `control_type` 字段，前端自动加载对应的控制卡片：

| control_type | 控制卡片类型 | 交互控件 | 适用设备 |
|--------------|-------------|----------|----------|
| boolean | 开关卡片 | 开关按钮（on/off） | 水泵、LED灯、电磁阀 |
| integer | 数值卡片 | 滑块（0-100）+ 数值输入 | 电机速度、风扇档位 |
| angle | 角度卡片 | 角度滑块（0-180/360）+ 角度刻度 | 舵机、阀门开度 |
| float | 精密数值卡片 | 精细滑块 + 小数输入 | 精确参数调节 |
| string | 指令卡片 | 指令下拉选择 / 文本输入 | 自定义指令 |

## WebSocket实时通信

### 消息类型

| 类型 | 方向 | 说明 |
|------|------|------|
| heartbeat | 双向 | 心跳检测 |
| sensor_data | 服务器→客户端 | 传感器数据更新 |
| actuator_status | 服务器→客户端 | 执行器状态更新 |
| command | 服务器→客户端 | 控制指令推送 |
| command_ack | 客户端→服务器 | 命令回执（硬件端） |
| command_status | 服务器→客户端 | 命令状态更新（通知前端） |
| area_update | 服务器→客户端 | 区域数据更新广播 |
| area_sync | 客户端→服务器 | 订阅区域数据 |

### 订阅区域示例

```json
{
    "type": "area_sync",
    "data": {
        "area": "温室1号区域"
    }
}
```

## 优势

1. **灵活扩展**：支持任意数量的传感器和执行器
2. **自动发现**：新设备首次上报自动注册
3. **自动分类**：设备自动识别并分类存储到对应表
4. **数据隔离**：通过 farm_id 实现多基地数据隔离
5. **兼容性好**：支持各种物联网协议和设备
6. **统一管理**：设备类型、ID规则、上报协议统一管理
7. **区域自动划分**：基于IP地址自动划分区域，同一IP设备归为同一区域
8. **多类型控制**：支持boolean、integer、angle、float、string五种控制类型
9. **回执确认机制**：发送指令后等待硬件回执，确保控制闭环
10. **超时提醒**：30秒未收到回执自动标记超时并提醒用户
11. **控制卡片自适应**：根据控制类型自动加载对应控制UI
12. **实时通信**：WebSocket支持实时推送和状态更新
